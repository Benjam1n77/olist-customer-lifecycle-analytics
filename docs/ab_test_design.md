# A/B 测试方案设计

> 本文档为**实验设计方案**，不是实验结果。
> 数据集没有任何真实营销触达记录，因此本项目只能设计实验，不能报告真实增量效果（Brief 第 19 节限制）。

设计依据（本项目实测数据）：

- 高价值已流失客户 10,915 人，历史支付占比 30.89%；
- 一次性购买率 97.00%，21 个成熟 Cohort 的加权 M1 留存率仅 0.48%；
- 首购未复购且仍在可挽回窗口（recency 14–180 天）的客户 33,527 人。

---

## 实验一：高价值流失用户召回

### 背景与假设

高价值已流失客户（`value_segment = high_value` 且 `lifecycle_stage = churned`）共 10,915 人，历史贡献约 31% 的支付金额。假设：个性化限期召回优惠能显著提升其 30 天复购率。

### 实验对象

`outputs/local/high_value_churned_customers.csv` 完整本地名单中的客户，排除近 7 天已被其他活动触达者（若有触达系统）。为精简仓库，完整派生名单不随 GitHub 发布；少量运营规则记录见 [真实样例说明](customer_samples.md)，不是实验数据。

### 分组设计

| 组别 | 处理 | 样本量 |
| --- | --- | --- |
| 对照组 | 不发送召回优惠（保持自然状态） | 约 5,457 人 |
| 实验组 | 发送个性化限期召回优惠（基于 favorite_category 的品类券，14 天有效） | 约 5,458 人 |

**随机分流方式**：以 `customer_unique_id` 的哈希值取模分流（`hash(id) % 100 < 50 → 对照组`），保证：

1. 分流确定性（同一客户重复进入实验时分到同组）；
2. 与任何业务变量无关，避免选择偏差；
3. 分流前做 AA 校验：比较两组的历史 total_payment、recency、评分分布，确认均衡。

### 指标体系

| 类型 | 指标 | 定义 |
| --- | --- | --- |
| 主要指标 | 30 天复购率 | 分流后 30 天内有 ≥1 笔 delivered 订单的客户占比 |
| 次要指标 | 支付金额 / 平均客单价 / 优惠券使用率 / 召回成本 / 增量收入 | 实验窗口内 |
| 护栏指标 | 退款率（canceled 占比）/ 投诉率（1 分评价占比）/ 平均折扣成本 | 防止优惠带来的负外部性 |

### 样本量估算

双侧检验公式（比例检验）：

\[
n = \frac{(z_{\alpha/2} + z_{\beta})^2 \left[ p_1(1-p_1) + p_2(1-p_2) \right]}{(p_1 - p_2)^2}
\]

假设（**标注为设计假设，非实测**）：基线 30 天自然复购率 \(p_1 = 3\%\)（参考本项目复购率 3.00% 的年化水平折算），最小可检测相对提升 20%（\(p_2 = 3.6\%\)），\(\alpha = 0.05\)、power \(= 0.8\)：

\[
n \approx \frac{(1.96 + 0.84)^2 \times (0.0291 + 0.0347)}{(0.006)^2} \approx 13{,}900 \text{ 人/组}
\]

名单总量 10,915 人不足以单组达到该样本量，两个应对方案：

1. 放宽 MDE 至相对 30%（\(p_2 = 3.9\%\)），单组需约 8,100 人，名单对半分仍不足 → 采用方案 2；
2. **延长实验窗口并累积新发生的高价值流失客户**（每月约新增数百人），或接受 80% power 降至约 65% 并在结论中标注检验功效不足。

### 分析计划

- 主要指标用双比例 z 检验，报告 95% 置信区间；
- 辅助用 logistic 回归控制 favorite_category、customer_state、历史 total_payment；
- 若护栏指标（退款率/投诉率）相对对照提升 > 20%，触发熔断复盘。

## 实验二：首购用户二购激励

### 背景与假设

一次性购买率高达 97.00%，加权 M1 留存率仅 0.48%——首购后早期干预是重要候选环节。假设：首购后 14 天仍未复购的用户，收到二购优惠 + 品类推荐可提升 30 天二购率。

### 实验对象

**滚动入组**：每日筛选"首购 delivered 订单满 14 天且尚未产生第二笔订单"的客户（与营销名单 SECOND_PURCHASE 规则一致的口径）。

### 分组设计

| 组别 | 处理 |
| --- | --- |
| 对照组 | 常规运营（不做额外触达） |
| 实验组 | 发送二购优惠（基于 favorite_category 的推荐 + 限时折扣） |

**随机分流方式**：入组时按 `hash(customer_unique_id + 入组日期) % 2` 分配；由于客户持续入组，属于序贯随机化，分析时按入组周分层。

### 指标体系

| 类型 | 指标 | 定义 |
| --- | --- | --- |
| 主要指标 | 30 天二购率 | 入组后 30 天内产生第 2 笔 delivered 订单的占比 |
| 次要指标 | 二购间隔（天）/ 二购金额 / 推荐类别点击率 | |
| 护栏指标 | 优惠成本 / 退款率 / 低毛利订单占比 | 防止补贴依赖 |

### 样本量估算

假设（**设计假设**）：基线 30 天二购率 \(p_1 = 4\%\)，MDE 相对 25%（\(p_2 = 5\%\)）。该基线不是由加权 M1 留存率 0.48% 换算而来；两者观察窗口和入组时点不同，正式实验前必须用目标入组人群的历史 30 天二购率重新估计：

\[
n \approx \frac{(1.96 + 0.84)^2 \times (0.0384 + 0.0475)}{(0.01)^2} \approx 6{,}700 \text{ 人/组}
\]

按数据期月均新增客户约 4,500 人估算，**每组 6,700 人约需累积 3 个月入组**（设计期规划，非实测）。

### 分析计划

- 主要指标：双比例 z 检验 + 按入组周分层的 Cochran-Mantel-Haenszel 检验；
- 二购间隔用 Kaplan-Meier 曲线 + log-rank 检验（删失 = 窗口结束未二购）；
- 子组分析：延迟订单经历者 vs 未经历者（检验履约体验是否削弱激励效果）。

## 共同原则

1. **不虚构结果**：本文档不含任何"提升了 X%"的结果表述；
2. **单一主要指标**：避免多重比较导致的假阳性，次要指标只做方向性参考；
3. **护栏优先**：护栏指标显著恶化时终止实验；
4. **可复现**：分流哈希算法、指标 SQL 口径与本项目 `docs/metric_definitions.md` 保持一致。
