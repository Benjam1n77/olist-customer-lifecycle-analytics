# 首购后 90 天二购驱动因素分析

> 本报告只使用 `mart_order_summary` 的实际记录和 Python 实际生成结果。文中的“驱动因素”指调整后的统计关联，不代表因果效应。

## 1. 业务问题

在全量有效客户中，一次性购买结构占主导。为了把“复购低”进一步拆成可执行问题，本专题回答：在拥有完整观察窗口的首购客户中，多少人会在 90 天内再次购买；哪些首单购买特征和首单体验与二购显著相关；哪些表面差异在控制客户州、品类和首购月份后不再显著。

## 2. 样本与指标口径

| 口径项 | 定义 |
| --- | --- |
| 客户主体 | `customer_unique_id` |
| 首购 | 客户最早一笔 `delivered` 订单 |
| 二购 | 首购后第 1–90 个自然日内最早出现的下一笔 `delivered` 订单 |
| 同日订单 | 排除，避免把同日拆单或同次购物会话当作行为复购 |
| 观察日 | 2018-08-30，即最大有效购买日期 2018-08-29 + 1 天 |
| 成熟样本 | 首购日期不晚于 2018-06-01，保证每人均有完整 90 天观察窗 |

## 3. 总体结果

| 指标 | 实际结果 |
| --- | ---: |
| 成熟首购客户 | 75,563 人 |
| 90 天跨日二购客户 | 980 人 |
| 90 天跨日二购率 | 1.2969% |
| 二购间隔中位数 | 29.00 天 |

## 4. 模型设计

模型使用二项分布 GLM，并报告 HC1 稳健标准误、调整后赔率比和 95% 置信区间。

- 购买时模型（n=75,563）：首单支付金额对数、运费占比、是否多商品、是否多卖家、是否分期，并控制客户州、主品类和首购月份。
- 首单体验模型（n=74,820）：仅使用配送状态和评分均可观察的客户，在购买时变量基础上加入配送延迟与低评分标记。
- 评价缺失不进入模型。评价缺失可能与平台记录机制或行为时间顺序相关，不能安全解释为业务驱动。

## 5. 核心发现

| 发现 | 实际分组率 | 调整后结果 | 解读 |
| --- | --- | --- | --- |
| 首单包含多个商品 | 多商品 1.7897%；单商品 1.2423% | OR=1.4099，95% CI 1.1349–1.7515，p=0.0019 | 与 90 天二购呈显著正向关联，可用于识别较高二购倾向的首购结构 |
| 首单低评分（1–2 分） | 低评分 0.9885%；高评分 1.3644% | OR=0.7371，95% CI 0.5835–0.9311，p=0.0105 | 与 90 天二购呈显著负向关联，支持在首单低评分后优先做体验修复 |
| 首单配送延迟 | 延迟 1.0588%；按时 1.3198% | OR=0.9127，95% CI 0.6890–1.2090，p=0.5242 | 描述性二购率较低，但控制其他变量后未发现显著关联 |
| 运费占比 | — | OR=1.0528，95% CI 0.9702–1.1424，p=0.2174 | 未发现显著关联 |
| 首单使用分期 | 分期 1.2782%；单次支付 1.3170% | OR=0.9598，95% CI 0.8368–1.1008，p=0.5575 | 未发现显著关联 |

## 6. 运营应用

1. 在首购后 29 天中位窗口内安排分阶段二购培育，但具体触达时点和优惠力度必须通过 A/B 测试验证。
2. 多商品首单可作为二购倾向标签之一，与价值和品类偏好共同用于排序，不直接视为因果策略。
3. 首单低评分客户优先进入服务补救，再进行二购激励，避免只发优惠而忽略体验问题。
4. 配送延迟对评分的负面关联在项目的独立履约分析中显著，但在本二购模型中未达到统计显著，两个结论回答的是不同结果变量，不能混用。

## 8. 限制

- 数据为历史观察性交易记录，模型只能识别条件关联。
- 数据缺少浏览、曝光、优惠券、营销触达、库存和价格变化等潜在混淆变量。
- 跨自然日口径用于降低同日拆单干扰，但无法识别所有同次购买或家庭共享账号场景。
- 90 天观察窗之外的二购不计入本专题结果，不能替代全生命周期复购率。
